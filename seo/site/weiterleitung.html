Weiterleitungen

Bei jedem Umzug entstehen sie zu Dutzenden, und niemand sieht sie sich danach noch einmal an. Dabei stehen die typischen Fehler nicht im Server-Protokoll, sondern in den Regeln selbst: eine Kette statt eines Sprungs, eine Schleife, eine Regel, die eine spätere verdeckt, ein 302, wo 301 gemeint war.

Fügen Sie Ihre Regeln ein — .htaccess, nginx oder eine schlichte Liste. Sie werden gelesen und durchgerechnet, nicht abgerufen.

Rechnet in Ihrem Browser. Es wird keine Adresse abgerufen, nichts gesendet, nichts gespeichert.

Regeln und Probeadressen Strg + Eingabe startet die Prüfung

Gelesen werden Redirect, RedirectMatch, RewriteRule mit R=, nginx rewrite und return im location-Block sowie Zeilen der Form /alt -> /neu. Kommentarzeilen mit # werden übergangen.

Diese Adressen werden durch den Regelsatz geführt. Das ist der einzige Weg, Regeln mit Mustern zu prüfen: ein Muster ist keine Adresse.

Was geprüft wird

Sechzehn Prüfungen, alle aus dem Text lesbar.

  • Ketten. Eine Adresse, die über zwei oder drei Stationen ans Ziel kommt. Jeder Sprung kostet eine Anfrage; die Regel sollte gleich auf die letzte Adresse zeigen. Ab vier Sprüngen wird es kritisch, denn irgendwann folgt kein Crawler mehr.
  • Schleifen. A zeigt auf B, B zeigt auf A. Der Browser bricht mit einer Fehlermeldung ab, die Seite ist für niemanden erreichbar. Auch der Sonderfall, dass eine Regel auf ihre eigene Adresse zeigt.
  • Verdeckte Regeln. Der Server nimmt die erste passende Regel. Steht weiter oben ein Muster, das die Adresse schon abfängt, kommt die spätere Regel nie zum Zug — sie sieht aber aus, als täte sie etwas.
  • 302 statt 301. Eine voruebergehende Weiterleitung sagt: die alte Adresse gilt weiter. Die Bewertung bleibt dann dort. Bei einem echten Umzug ist 301 oder 308 richtig.
  • Fehlender Statuscode. Ohne Angabe sendet Apache 302, nginx leitet gar nicht um. Beides ist selten gemeint.
  • Muster ohne Anker. Ein Ausdruck ohne ^ und $ passt auch mitten in der Adresse und leitet mehr um als gewollt.
  • Alles auf die Startseite. Zeigt eine gelöschte Seite auf die Startseite, wertet Google das häufig wie eine Fehlerseite. Ehrlicher ist die nächstliegende passende Seite — oder ein 410.
  • Verlorener Abfrageteil. Steht im Ziel einer RewriteRule ein Fragezeichen, ersetzt Apache die ursprüngliche Abfrage. Ohne die Flagge QSA sind Angaben wie ?seite=2 danach weg.
  • Regel ohne Abschluss. Ohne L arbeitet Apache die folgenden Regeln weiter ab — eine häufige Quelle für Doppelsprünge, die niemand sucht.
  • Uneinheitliche Ziele. http neben https, www neben ohne www, Schrägstrich mal so mal so: jede dieser Mischungen erzeugt hinter der Weiterleitung einen zweiten Sprung.

Dazu doppelte Quellen, Sprungmarken im Ziel, internes Umschreiben ohne Weiterleitung, als entfernt gemeldete Seiten und die Zeilen, die nicht gelesen werden konnten — die werden genannt, statt stillschweigend zu fehlen.

Grenzen

Was hier nicht geht.

  • Der Server wird nicht gefragt. Was er wirklich sendet, sieht nur, wer ihn abruft — und fremde Antwortköpfe darf der Browser nicht lesen. Hier wird gerechnet, was Ihre Regeln bedeuten. Wenn davor eine andere Regel, ein Vorschaltserver oder das Hosting-Panel eingreift, sieht das dieses Werkzeug nicht.
  • Bedingungen werden nicht ausgewertet. RewriteCond und nginx-if stehen oft über einer Regel und schränken sie ein. Sie werden hier nicht mitgerechnet; eine Regel gilt in der Auswertung immer.
  • Kein Vergleich mit Ihrer Website. Ob das Ziel einer Weiterleitung existiert, weiß nur, wer es abruft. Der Crawl auf der Kommandozeile tut genau das.
